## 1. 切片建议的采纳与偏离审计

`design.md` 的 `### D-A8 切片与依赖`（`design.md:257-270`）给出了 S1–S6 六张切片与语义依赖表，
已经过设计审与人类门。本次出票**默认整体采纳**该划分：Task 1–6 与 S1–S6 一一对应，
`Blocked-by` 取 D-A8 的依赖列并落到真实票号（`design.md:262-268`）。

| 切片 | 票 | 依赖（D-A8） | 落盘 Blocked-by |
|---|---|---|---|
| S1 后端鉴权与托管骨架 | Task 1 | 无 | none |
| S2 运行时设置 | Task 2 | S1 | 1 |
| S3 数据端点 | Task 3 | S1、S2 | 1, 2 |
| S4 前端骨架与总览 | Task 4 | S1、S3 | 1, 3 |
| S5 管理页 | Task 5 | S4 | 4 |
| S6 交付与视觉验收 | Task 6 | S5 | 5 |

**切片偏离：无。** 未增删票、未合并票、未改阻塞边、未改切片边界。Task 7 是技能恒定的
「实现验证」收尾票（不计入功能票预算），不构成对 D-A8 的偏离。

**预算核对**：功能票 6 张（Task 1–6），处于 3–6 张预算上限内；收尾票 1 张不计预算。
Task 5 覆盖五个管理页，是本 change 最大的单票；不拆分的理由：D-A8 已把前端页面归为一张
S5 切片，拆分会使功能票变 7 张、越过预算上限，且五页共享同一套表单/三态/URL 状态机制，
拆开会把同一机制的验收重复四遍（开发循环镜：心智负担与重复验收 > 单票体积）。

## 3. 承重约束 → 票映射

下表「承载位置」指该票内实际承担该约束的验收条目（票号见 `tickets.md`）。

| 约束 | 摘要 | 票 | 承载的验收条目 |
|---|---|---|---|
| C1 | 管理面鉴权收敛在单一依赖 | 1 | 「双轨鉴权」条目（Bearer/cookie/CSRF 全部经同一依赖；login 是唯一豁免） |
| C2 | 面板与 API 必须同源 | 1 / 6 | Task 1「静态托管」条目（同进程同源托管）；Task 6「镜像冒烟」条目（单端口 8000 下 / 与 /api 同源） |
| C3 | 现状没有面板/静态托管/镜像前端阶段 | 1 / 6 | Task 1「静态托管」条目（含产物缺失 404）；Task 6「离线镜像构建」条目（Node 阶段产出 dist 到 /app/static） |
