### Task 1: 后端鉴权、安全头与静态托管骨架

交付 cookie + CSRF 双轨管理鉴权（保留 Bearer），补齐安全响应头与同源静态托管骨架。
对应 S1。

- R-ID: R-ADM-01, R-PANEL-11, R-PANEL-12
- Blocked-by: none

**验收标准**

- [x] 登录响应同时返回 `token`、`expires_in`、`csrf_token`，并设置会话 cookie（`HttpOnly`、`SameSite=Lax`、`Path=/`、`Max-Age=session_ttl`）与可被前端读取的 CSRF cookie；请求经 HTTPS 或受信反代声明的 HTTPS 时两者都带 `Secure`。
- [x] 双轨鉴权：Bearer 有效可用；Bearer 存在但无效时直接 401 且不回退 cookie；cookie 会话可用于 GET；cookie 来源的写方法缺 `X-CSRF-Token` 或值不符返回 403，值相符才执行；Bearer 来源豁免 CSRF；`/me` 返回用户名与 CSRF 值并在 CSRF cookie 缺失时补发；`/logout` 返回 204 并清空两个 cookie；OpenAPI 文档含 Bearer security scheme（`/docs` 的 Authorize 可用）。
- [x] 安全响应头：所有响应含 `X-Content-Type-Options: nosniff`、`Referrer-Policy: no-referrer`、`X-Frame-Options: DENY`、`Permissions-Policy`；面板入口、静态资源与深链接回退响应含 CSP（`script-src 'self'`，不含 `'unsafe-inline'`）；`/docs` 与 API 响应不带 CSP；管理 API 响应带 `Cache-Control: no-store`；超大请求体的 400 响应同样带齐上述安全头（安全头覆盖到 body-limit 拒绝路径）。
- [x] 静态托管：产物存在时根路径与无扩展名的未知深链接返回面板入口且 `Cache-Control: no-store`，`/assets/*` 返回资源且带一年 immutable 缓存；带扩展名的缺失文件、以及 `api/`、`v1/`、`healthz` 前缀的未知路径返回 JSON 404，不被回退成 HTML；越界路径（含 `..`）不被读取；产物缺失时根路径返回 404 且错误码为 `FRONTEND_NOT_BUILT`（message 固定），公共与管理 API 不受影响。
- [x] 既有后端测试全部通过；测试客户端同时支持 Bearer 与 cookie 两种认证方式，原有用例无一被削弱或删除。

### Task 2: 运行时设置

新增 settings 持久化与进程内运行时设置，使缓存参数、请求总预算、账号默认超时可在线修改并即时生效。
对应 S2。

- R-ID: R-ADM-08, R-SCH-03, R-CAC-02
- Blocked-by: 1

**验收标准**

- [x] 新迁移可 `upgrade` → `downgrade` → `upgrade` 往返成功；settings 表结构为 `key TEXT` 主键、`value TEXT NOT NULL`、`updated_at DATETIME NOT NULL`，降级删除该表。
- [x] 启动时以环境变量默认值为基线合并库内存量覆盖值；非法或超范围的存量值被忽略并记 warning，启动不失败；运行时设置随应用状态可被端点读取。
- [x] 缓存参数变更后缓存被重建（条目归零）且新参数立即生效；参数不变时不重建；缓存开关关闭时不再写入新条目。
- [x] 请求总预算调大/调小都作用于该请求的真实总耗时（含并发信号量等待），不是只改单次上游调用超时；未显式指定超时的新建账号使用当前运行时默认超时；已存账号的超时不被运行时默认值覆盖。
- [x] `GET /api/admin/settings` 返回可编辑项当前值与只读项快照（含版本、上传上限、并发、会话时长、面板产物是否就绪）；`PUT /api/admin/settings` 支持部分字段更新，非法值、未知键、显式 `null` 一律 400 且带字段级 `error.fields`（含字段名与原因），此时库与运行时都不变；提交成功后返回全量可编辑项与缓存是否被清空，新值立即生效且重启后保持。
- [x] 数据库写失败返回 500，事务回滚、运行时不应用；并发 PUT 后库值、运行时值与重启后读到的值三者一致；设置保存 p95 < 500ms（本机 SQLite 实测并记录）。

### Task 3: 数据端点

补齐总览、用量序列与日志/账号查询的数据面。对应 S3。

- R-ID: R-ADM-06, R-ADM-09, R-ADM-10
- Blocked-by: 1, 2

**验收标准**

- [x] `GET /api/admin/overview` 返回今日指标（请求/成功/失败/缓存/配额、成功率、缓存命中率、平均延迟；请求数为 0 时比率为 `null`）、自动路由失败单独计数、厂商账号数与瞬时可调度数、账号配额用量、近 7 个本地日序列、最近 10 条错误（含账号名称、不含 OCR 原文）、缓存状态；读取过程不触发账号状态迁移。
- [x] `GET /api/admin/usage/series` 按 Asia/Shanghai 本地日分桶、范围内缺日补零、默认 7 个日桶，并支持成员/厂商/账号过滤；`GET /api/admin/usage/summary` 每行增加平均延迟与显示名（已删除实体为 `null`、`auto` 为「自动路由」），按 key 升序且 `null` 最后。
- [x] 三个查询端点共用时间口径：接受 ISO 时间或 `YYYY-MM-DD`；仅日期形式的结束值包含当日（半开区间，次日 00:00 不计入）；`from` 晚于 `to` 返回 400；跨度超过 90 个本地日返回 400（summary 同样受限）。
- [x] `GET /api/admin/logs` 支持起止时间与错误码过滤，返回同过滤条件下的总数与每行的用户名/账号名（已删除为 `null`），保持 limit/offset 与 id 倒序，空结果返回空行集与 0 总数。
- [x] `GET /api/admin/accounts` 每行增加贡献者名称与配额用量（日/月/总量，含限额与周期键）；成功识别后三个周期用量递增，跨日重置后日用量归零，删除账号后其内存配额计数被清理（连续两次 flush 无外键错误）。
- [x] 10 万条用量事件基准下，序列、汇总与日志查询 p95 均 < 300ms；基准用例注册为 slow、默认套件不跑，实测 p50/p95 与命令记入本票报告。
